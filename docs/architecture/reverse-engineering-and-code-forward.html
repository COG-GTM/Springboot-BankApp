1. Goals

  • This is not a platform upgrade. The runtime (Spring Boot 3.3.3, Java 17, MySQL 8) stays as it is; no application code is changed by this exercise.
  • Build an evidence-backed knowledge base of the system as it actually behaves: modules, who writes which table, business rules as implemented, integration points and their contracts.
  • Propose a domain-driven re-architecture (bounded contexts, ownership, events) and an incremental strangler roadmap whose slices each have a measurable "done when".
  • Scope: one Maven module, 8 Java classes, 4 Thymeleaf templates, 2 Jenkins pipelines, raw Kubernetes manifests and a Helm chart. No mainframe, queue or file-feed artefacts exist in the repo (rg -i "copybook|ebcdic|COMMAREA|@JmsListener|sftp" → 0 hits), so the legacy-touchpoint section is not applicable.

6. Re-architecture proposed

The ownership table yields one core domain (money movement), one supporting domain (identity), two read models and one adapter for everything outside the JAR. Contexts talk only through commands (imperative) and events (past tense).

Design rules

  • One writer per table; a context's tables are reachable only through its commands.
  • Money value object (scale 2, currency, > 0) at every boundary — replaces raw BigDecimal.
  • Injected Clock; one postedAt per operation; posting date is a domain field.
  • Every command runs in one @Transactional unit; balance carries @Version; entries are immutable and double-entry.
  • The security principal is never a persistence entity.
  • Events are the only way data crosses a context; the UI reads projections, never entities.
  • Schema changes only through migrations; no secret literal in the repository; one image name and one config source.
